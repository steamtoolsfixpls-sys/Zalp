# Architecture and module contract

Static ES-module browser game: no bundler, `index.html` loads `battle_engine.js`; three.js r170 and
Rapier 0.14 come from the import map. Units are metres/seconds/radians, Y is up.

- **Soldiers** face local **+Z** (`root.rotation.y = atan2(dx, dz)`), `root.position` is at the feet.
- **Vehicles** face local **-Z**; `vehicle.mesh` origin is on the ground under the hull centre.
- **Player camera** looks along `(-sin(yaw)·cos(pitch), sin(pitch), -cos(yaw)·cos(pitch))`.

## Layout

| Path | Role |
|---|---|
| `battle_engine.js` | Kernel: shared state, boot, frame loop. Keep it small. |
| `src/core/*` | `events`, `settings`, `quality`, `input`, `assets`, `pool`, `spring` |
| `src/modules.js` | Registry of mixins and feature modules |
| `src/**/<mixin>.js` | Legacy gameplay methods installed on `BattleEngine.prototype` (`this` = engine) |
| `src/**/<module>.js` | Feature modules: `create<Name>(engine)` returns the module object |
| `physics_ragdoll.js` | Rapier world: vehicles, ragdolls, debris, soldier hitboxes |
| `stats.js` | Frozen tuning tables (weapons, vehicles, model list) |
| `tools/` | Dev server, headless smoke runner, asset pipeline |
| `individual_models/` | Optimized GLBs (meshopt + KTX2) + `manifest.json`; generated by `npm run assets` |

## Kernel

Frame order in `engine.tick(dt)` (skipped while `!isStarted || isPaused`):
`physics.step` → `updateReloadStateMachine` → `updatePlayerController` → `updateUnitsAndSquadAI` →
`updateAutonomousDrones` → `updateProjectiles` → `updateEffects` → modules `update(dt)` → modules `lateUpdate(dt)`.
Then always: `quality.update(dt)` and `render(dt)`.

Shared services on the engine: `events`, `settings`, `quality`, `input`, `assets`, `physics` (alias
`ragdollPhysics`), `sound`, `octree` (static world for the player capsule), `scene`, `camera`,
`cameraMount` (eye position), `renderer`, `sunLight`, `time` (s), `frame`, `wind` (Vector3 m/s),
`hudLayer` (DOM), `raycaster`.

### Feature modules

`src/modules.js` lists `[name, factory]`. The kernel sets `engine[name] = factory(engine)` and calls the
optional hooks: `install(engine)` (may be async, runs after the world is built), `update(dt)`,
`lateUpdate(dt)`, `onStart(faction)`, `onResize()`. A hook that throws is logged; five failures disable the
module, never the frame loop.

Rules for module code:
- Talk to other modules through **events first**. Direct calls must be defensive
  (`engine.vfx?.explosion?.(...)`): a module may be absent or still a stub.
- No per-frame allocation in hot paths (particles, bullets, tracers, decals, casings): preallocate and
  recycle (`src/core/pool.js`), never `new`/`dispose()` geometry or materials during combat.
- Scale work with `engine.quality.profile` and re-read it on `quality:changed`.
- Create your own DOM under `engine.hudLayer`; inject CSS with one `<style>` element. UI text is Russian.
- New keys go through `engine.input.bind(code, handler, { priority })`. A handler returning `true`
  consumes the key. Mouse buttons are `MouseLeft` / `MouseRight` / `MouseMiddle`.
- Player-facing messages: `engine.notify(text, { kind: 'info'|'warn'|'danger', ttl })`.
- No new CDN/runtime dependencies beyond the import map (`three`, `three/addons/*`, Rapier).

### Modifiers

`engine.addModifier(name, fn)` registers a factor; `engine.modifier(name)` returns the product.
Names: `playerSpeed`, `canSprint` (0/1), `canFire` (0/1), `aimSway`, `recoil`. The player controller
and weapon code apply them; health, suppression, carrying etc. contribute.

### Overrides

- `engine.controlOverride = (dt) => true` takes over the player controller for that frame (drone and
  cut-scene cameras). Clear it to return control.
- `engine.lookOverride = (dx, dy) => true` consumes look input.
- `engine.customRenderHook = (renderer, scene, camera, dt)` replaces the final render (post-processing).
- `engine.baseFov` is the unzoomed field of view (from settings). Sights and optics set
  `camera.fov = baseFov / zoom` and restore `baseFov` when done.

## Entities

**Unit** (`engine.units[]`): `id, name, faction ('RU'|'UA'), role ('rifleman'|'at'|'medic'|...), weaponKey,
slotIndex, isAlliedDesant, homePos, homeYaw, root (Group), bones {hips, spine, chest, head, upperArmL/R,
lowerArmL/R, handL/R, upperLegL/R, lowerLegL/R, footL/R}, modelNode, hp, maxHp, isDead, isWounded,
mountedVehicle, moveTarget, velocity (world m/s, written by AI), stance ('stand'|'crouch'|'prone'),
aimPoint (Vector3|null), suppression (0..1), fireTimer, flinchAmount, respawnCountdown, hitboxes[]`.
Modules attach their own state as `unit.animator`, `unit.ai`, `unit.gear`.

**Vehicle** (`engine.physics.vehicles[]`): `id, spec (STATS.VEHICLE_SPECS), name, faction, mesh, hitProxyMesh,
hp, maxHp, destroyed, controls {throttle, steer, brake, aiAutopilot, aiTargetZ}, turretYaw (world target),
turretPitch (target), fireTimer, speedKmh, chassisPos, chassisQuat, frameDeltaPos, suspPoints[{local,
compression, grounded}], desantUnits[], playerSeatedMode, playerDesantSlot`. Never touch `vehicle.body`
outside the physics layer; use `engine.physics.applyVehicleImpulse(vehicle, impulse, worldPoint)`.
Modules attach `vehicle.parts` (visual rig), `vehicle.modules` (damage), `vehicle.crew` (AI).

**Player** (fields on the engine): `playerCollider` (Capsule; `end` is the eye), `playerVelocity`, `yaw`,
`pitch`, `isCrouching`, `isSprinting`, `isAiming`, `isFiring`, `playerHp`, `playerFaction`, `loadoutKeys`,
`currentWeaponIdx`, `weaponStates`, `viewmodelRoot`, `playerVehicleState {vehicle, role 'DRIVER'|'DESANT',
desantSlotIndex, thirdPersonCamera}`, `fpvMode`, `squadOrderMode`.

Hit targets for bullets are three.js meshes: soldier hitboxes (`userData.isSoldierHitbox, unit, zone,
partName`), vehicle proxies (`userData.isVehicleHitbox, vehicle`) and `engine.staticShootableMeshes`.
Static meshes may carry `userData.surface` (`dirt|concrete|metal|wood|sandbag|glass|foliage`) and
`userData.penetrable = { mm, material }` for wall-bang.

## Keys

Existing: `WASD`, `Shift`, `Space`, `C` crouch, `Q/E` lean, `R` reload, `F` drive, `B` ride armor, `H` squad
mount, `T` autopilot, `K` camera, `V` FPV, `N` Lancet, `G` assault, `1-4` weapons, LMB fire, RMB aim.

Reserved for new features: `X` fire selector · `Y` magazine check · `L` flashlight · `P` laser ·
`5` frag grenade · `6` smoke grenade · `7` TM-62 mine · `8` bandage · `9` tourniquet · `0` painkiller ·
`Z` optic zoom · `J` vehicle smoke launchers · `O` hatches/doors · `U` Mavic 3 · `M` tactical map ·
`Esc` settings · `Tab` lobby/loadout · `F` also loots (higher priority handler, only when a lootable is
nearer than any vehicle) · in the gunner seat `1-4` select shell type.

## Graphics presets

`engine.quality.profile` (see `src/core/quality.js`): `maxPixelRatio, resolutionScale, msaa, drawDistance,
dynamicResolution, shadows, lighting, textures, lod, anim, particles, decals, debris, ragdolls, smoke,
postfx, audio, physics`. Presets: `low`, `medium`, `high`, `ultra`; `auto` picks by device.

## Testing

```
npm run smoke                                   # regression scenario, must stay free of page errors
node tools/smoke.mjs <scenario.mjs> --out /tmp/shots/x --query "quality=low&dynamicResolution=false"
node tools/smoke.mjs tools/scenarios/views.mjs --out /tmp/shots/x --views "name:px,py,pz,tx,ty,tz;..."
```

Scenarios drive the game through `window.BATTLE_ENGINE.instance` and `window.BATTLE_ENGINE.step(n, dt)`
(fixed simulation steps without rendering). Headless Chrome renders in software: prefer `quality=low`,
few screenshots, and stepping over waiting. The runner allows two concurrent runs machine-wide.
